# Milestone 1 — playable stem extraction vertical slice

## Preconditions
M0 research and DR-0001 reviewed. If unresolved, implement only the upload/playback scaffolding and research harness, not a permanent model integration.

## Scope
Single-user local web app; upload an authorized short WAV/MP3 file; record rights/source metadata; start one separation job; poll progress; play original and resulting stems with solo/mute; report errors and timings. Store input hash, model/version/params and output metadata. Simple persistence and cleanup.

## Deliverables
Working browser UI and API, separation adapter, reproducible development setup, fixture generator, unit/API/integration tests, README runbook, proof record under `docs/proof/`.

## Acceptance tests
- Valid authorized audio imports and plays; unsupported/corrupt/oversized inputs fail clearly.
- Job transitions queued → running → succeeded/failed; failures don't leave orphaned running state.
- Every output is accessible, playable, labeled, tied to source and processing config.
- Solo/mute and original-versus-stem playback work; UI remains responsive during processing.
- No rights metadata is dropped; no protected-stream extraction path exists.
- Runs on documented supported development environment without paid API.
- Integration tests use licensed/synthetic fixtures and do not require downloading protected music.

## Out of scope
Clip trimming, advanced timeline, MIDI, vocal generation, video, Spotify extraction, cloud deployment, subscriptions.

## Definition of done
Proof evidence and exact commands recorded; lint/type/test/build green; known quality limits documented; independent review completed; no merge without approval.
